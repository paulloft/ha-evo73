# EVO73 / Home Assistant

Дополнение Home Assistant для домофонов EVO73: авторизация, открытие двери, видео и снимки камеры, вебхук при входящем звонке. Правила действуют для всего репозитория.

## Стек и зависимости

- Сервер: TypeScript 7, Node.js ESM, Express 5. Запуск исходников через `node --import=tsx src/index.ts`, без компиляции сервера. Docker и CI используют Node.js 26.
- Интерфейс: React 19, React Router 7, TypeScript, Bootstrap 5, SCSS, hls.js.
- Сборка интерфейса: Webpack и esbuild. Проверка типов — отдельным `tsc` с `noEmit`. Серверные JS-файлы и каталог `dist/` не создавать.
- ESLint проверяет JS/MJS-конфиги; TS/TSX проверяются TypeScript в строгом режиме. Не описывать отсутствующие правила React Hooks как включённые проверки.
- Использовать npm workspaces и единый корневой `package-lock.json`. Зависимости интерфейса добавлять в workspace `app`, серверные — в корень.
- При добавлении или обновлении зависимостей выбирать актуальные стабильные версии, проверять совместимость. Не понижать TypeScript 7 ради плагинов.
- Не возвращать Babel, Oxlint, ts-loader и несовместимые с TypeScript 7 проверки типов. Не добавлять dotenv: загрузка локального окружения уже реализована в проекте средствами Node.js.
- Не переносить зависимости, плагины и настройки из соседних проектов без реальной потребности. В частности, не создавать `src/Assets` ради скопированного конфига.

## Структура

```text
src/                  серверный TypeScript
  Evo/                API EVO и авторизация
    AuthResponse.ts   проверка форматов ответов авторизации
  Sip/                SIP-протокол, TCP, Digest и регистрация
    FrameBuffer.ts    сборка SIP-сообщений из TCP-потока
  SipAgent.ts         управление SIP-клиентами и уведомлениями
  Actions.ts          действия и отправка вебхука
  Routes.ts           регистрация HTTP-маршрутов
  Webserver.ts        HTTP-сервер
  Types.ts            общие типы API
app/src/              React-приложение
app/public/           исходный HTML-шаблон и favicon
app/webpack.config.js конфигурация сборки интерфейса
tests/                тесты node:test и локальный SIP-сервер
rootfs/               запуск дополнения в Home Assistant
config.yaml           настройки дополнения
public/               собранный интерфейс
var/                  локальные материалы и сторонние исходники
```

`var/evo73-ha` — Python-форк для сравнения поведения протоколов. Использовать как справочный материал; исправления вносить в основной TypeScript-проект.

## Команды

Запускать из корня репозитория:

```sh
npm ci                         # установка по lock-файлу
npm run dev                    # сервер с перезапуском
npm run watch --workspace app   # наблюдение за интерфейсом
npm run typecheck              # типы сервера, тестов и интерфейса
npm run lint                   # typecheck и ESLint
npm test                       # тесты
npm run check                  # lint и тесты
npm run build                  # production-интерфейс
npm start                      # запуск серверного TypeScript
```

После изменения поведения запускать подходящие тесты и `npm run check`; при изменении сборки или зависимостей — также `npm run build`. Для правок только документации сборка и тесты не требуются. Новые тесты должны проверять поведение и регрессии, а не повторять реализацию. В отчёте отделять локальные проверки от проверки на реальном домофоне и в Home Assistant.

## Соглашения по коду

- Новый прикладной код писать на TypeScript; компоненты — в `.tsx`.
- Сохранять строгую типизацию, не использовать `any`. Внешние данные и ошибки принимать как `unknown`, проверять перед использованием.
- Использовать `import type` для типов. В серверных относительных импортах сохранять расширение `.js`, как требует NodeNext.
- Все блочные операторы (`if`, `else`, `for`, `while`, `do...while`) оформлять с фигурными скобками, даже для одной инструкции.
- Не подавлять проблемы через `eslint-disable`, `@ts-ignore`, `@ts-nocheck` или ослабление конфигурации. Исправлять причину.
- Предпочитать именованные экспорты для новых утилит; сохранять принятый интерфейс существующих модулей без массовых переименований.
- Не проводить попутное форматирование всего проекта. Применять соглашения к новому и изменяемому коду.
- Использовать существующие API-обёртки и общие типы, не дублировать обработку HTTP и токенов в компонентах.
- Асинхронные операции должны иметь обработку ошибок. Для фоновых операций недостаточно одного `void`: отклонение Promise должно быть обработано.

### React и стили

- Один React-компонент на `.tsx`-файл.
- Данные маршрутов загружать через loaders React Router и `sendRequest` из `app/src/Utils.ts`; пользовательские действия выполнять в обработчиках событий.
- Не хранить в state значения, вычисляемые из props или других состояний. Избегать синхронного `setState` в `useEffect`, если значение можно вычислить при рендере.
- `useMemo` и `useCallback` применять при конкретной необходимости. Не переносить отсутствующие в проекте хуки из других репозиториев.
- Эффекты должны освобождать ресурсы: подписки, таймеры, плееры и запросы, когда требуется отмена.
- Использовать классы Bootstrap; дополнительные стили размещать в SCSS компонента. Не добавлять inline-стили.
- Цвета брать из темы Bootstrap через CSS-переменные; не вводить отдельную палитру без задачи на изменение дизайна.
- Сохранять hash-маршрутизацию и относительные URL ресурсов/API для Home Assistant ingress. Не заменять их абсолютными путями от `/`.

## Авторизация, SIP и вебхуки

- Сохранять разделение токенов SingleAuth, основного API и домофона, их обновление и существующие имена файлов хранилища.
- Не выводить в логи пароли, токены, Digest-заголовки и полные SIP-сообщения с секретами.
- SIP нужен для наблюдения за звонком: на `INVITE` отправлять `180 Ringing`. Не отвечать `200 OK` на `INVITE`, принимая звонок вместо телефона.
- Сохранять TCP, keepalive, продление до истечения регистрации и повторные попытки после отказов, таймаутов и разрывов. Ошибка начальной загрузки устройств не должна навсегда отключать SIP.
- Повторные `INVITE` одного звонка не должны отправлять несколько вебхуков. Дедупликация по `Call-ID` действует отдельно для каждого домофона, выполняется до HTTP-запроса и сохраняется при замене SIP-клиента. История должна быть ограничена по размеру.
- Ошибка вебхука не должна останавливать SIP или повторно уведомлять о том же звонке. Новый звонок должен обрабатываться независимо.
- Состояние Digest и ожидающие ответы хранить отдельно для клиентов. При продлении регистрации сохранять Call-ID и From tag, увеличивать CSeq.
- Проверять эти сценарии через локальный SIP-сервер и HTTP-моки. Автотесты не должны открывать реальную дверь, запрашивать звонок/СМС или отправлять реальные уведомления.

## Поиск и работа с файлами

- Для семантических задач (все использования, типы, определения, безопасное переименование) предпочитать доступные инструменты индекса PhpStorm. Если подходящего инструмента нет, использовать узкий поиск и проверку TypeScript.
- Для текстового поиска использовать `rg`, для списка файлов — `rg --files`. Известный файл читать напрямую; большие файлы — нужными фрагментами через `sed` или `rg -n`.
- Сначала сужать поиск по каталогу и шаблону. Не сканировать `node_modules`, сборочные каталоги и весь `var/` без необходимости.
- Не читать повторно уже полученные фрагменты и не дублировать результаты семантического поиска текстовым без причины.
- Не редактировать вручную корневой `public/`, `node_modules/` и другие генерируемые файлы. `app/public/` содержит исходники и может редактироваться.
- Не добавлять в Git локальные токены, `.env.local`, логи, APK и сторонние исходники из `var/`.
- Сохранять существующие пользовательские изменения; не выполнять reset, очистку рабочего дерева, commit или push без соответствующей задачи.
- При изменении команд, настроек и поведения обновлять относящиеся к ним разделы README.
