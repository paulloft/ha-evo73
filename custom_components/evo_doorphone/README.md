# EVO Doorphone

Интеграция подключает Home Assistant к локальному дополнению EVO. Нужны Home Assistant 2026.10 или новее и дополнение EVO 1.2.0 или новее.

Для каждого домофона автоматически создаётся устройство с четырьмя сущностями:

- **Открыть дверь** (`button`) — открытие первой двери этого домофона.
- **Камера** (`camera`) — снимок и живое HLS-видео через стандартный плеер HA.
- **Звонок** (`event`, класс doorbell) — событие `ring` при входящем SIP-звонке.
- **Жду курьера** (`switch`) — одно открытие первой двери при следующем входящем звонке с автоматическим выключением режима.

Новые домофоны добавляются при обновлении списка устройств раз в минуту. Если домофон исчез из списка или дополнение недоступно, его сущности становятся недоступными. События звонка поступают сразу через длительный HTTP-запрос; после обрыва соединение восстанавливается автоматически.

## Установка через HACS

1. Установите или обновите дополнение EVO и авторизуйтесь в его веб-интерфейсе.
2. В HACS откройте меню → **Пользовательские репозитории**. Добавьте `https://github.com/paulloft/ha-evo73` с типом **Интеграция**.
3. Скачайте **EVO Doorphone** и перезапустите Home Assistant.
4. Откройте **Настройки → Устройства и службы → Добавить интеграцию → EVO Doorphone**.
5. Укажите внутренний адрес дополнения. Для установки из `paulloft/ha-addons-repo` по умолчанию используется `http://961868a2-doorphone` (порт 80).

Адрес должен быть доступен из контейнера Home Assistant Core. Не используйте ссылку `/api/hassio_ingress/...` из браузера: она требует пользовательской сессии. Для отдельного сервера используйте его адрес и порт, например `http://192.168.1.10:8099`.

Можно установить вручную: скопировать папку `custom_components/evo_doorphone` в одноимённую папку конфигурации HA, перезапустить HA и выполнить шаги 4–5. Редактировать `configuration.yaml` не требуется.

Если ранее была установлена интеграция Python-форка, замените её папку новой версией и удалите старые YAML-настройки `evo_doorphone`, `button: platform: evo_doorphone` и `camera: platform: evo_doorphone` перед перезапуском. Новая интеграция настраивается через UI.

### Иконка интеграции

Home Assistant загружает иконку из `custom_components/evo_doorphone/brand/icon.png`. Поле с URL иконки в `manifest.json` не требуется. После обновления интеграции нужен полный перезапуск Home Assistant: список файлов интеграции кешируется при загрузке.

Обновление дополнения EVO не обновляет интеграцию в `custom_components`. Если иконка отсутствует в **Настройки → Устройства и службы**, повторно скачайте интеграцию через HACS и проверьте наличие `/config/custom_components/evo_doorphone/brand/icon.png`, затем перезапустите Home Assistant.

Отображение в самом HACS зависит от его интерфейса. В HACS 2.0.5 известна [ошибка загрузки локальных иконок](https://github.com/hacs/integration/issues/5223): карточка использует внешний каталог брендов вместо локального файла. Это отдельная проблема от отображения интеграции в настройках Home Assistant.

## Использование

Устройства и сущности находятся на странице интеграции. Камеру можно добавить на стандартную карточку HA; живое видео воспроизводится средствами интеграции Stream.

После успешного открытия двери дополнение сбрасывает текущий входящий звонок этого домофона через SIP (`603 Decline`). Это работает и для кнопки «Открыть дверь», и для режима «Жду курьера». При ошибке открытия звонок не сбрасывается.

Для автоматизации уведомления используйте сущность **Звонок** нужного домофона. Она меняет состояние на время события, атрибут `event_type` принимает значение `ring`. Атрибуты `call_id` и `call_timestamp` позволяют определить конкретный звонок. Повторные SIP-пакеты одного звонка не создают повторных событий.

Кнопка «Имитировать звонок» в веб-интерфейсе дополнения создаёт тестовое событие HA без реального звонка.

«Жду курьера» выполняется в дополнении и работает при потере связи с HA. Режим сбрасывается перед попыткой открытия, в том числе при ошибке команды, и после перезапуска дополнения. Повторные пакеты звонка не открывают дверь снова. Имитация звонка не открывает дверь и не выключает режим. Состояние переключателя обновляется после события звонка и при опросе устройств раз в минуту; команды из HA сразу обновляют состояние сущности. Если дополнение ещё не поддерживает режим, переключатель недоступен — обновите дополнение отдельно от интеграции.

`webhook_url` в настройках дополнения можно оставить пустым. Если URL указан, старый вебхук продолжит работать независимо от интеграции. Если уже настроено уведомление через вебхук, отключите соответствующую автоматизацию при переходе на событие HA, чтобы два разных способа уведомления не дублировали друг друга.

При изменении адреса откройте меню интеграции → **Перенастроить**. Постоянный ID дополнения защищает от случайного подключения к другому экземпляру и от создания дубликатов при повторном добавлении. Сохраняйте каталог настроек дополнения при переустановке: в нём находится `ha_instance_id` вместе с токенами.

Список последних 256 звонков хранится в памяти дополнения для восстановления после коротких разрывов связи. После перезапуска HA или самого дополнения старые звонки не воспроизводятся заново. Это канал текущих событий, а не постоянный архив звонков.

## API и проверки

Интеграция использует `/ha/info`, `/ha/devices`, `/ha/snapshot`, `/ha/stream`, `/ha/events`, `POST /ha/open` и `POST /ha/courier`. Токены EVO и SIP-пароли остаются в дополнении. Дополнение должно находиться в доверенной локальной сети; его HTTP API не предназначен для публикации в интернете.

Тесты работают с настоящим ядром Home Assistant и локальным тестовым API:

```sh
docker run --rm --entrypoint python \
  -v "$PWD:/workspace:ro" -w /workspace \
  ghcr.io/home-assistant/home-assistant:stable \
  -m unittest discover -s tests/homeassistant -v
```
